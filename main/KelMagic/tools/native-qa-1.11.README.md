# Нативные стенды 1.11 (только разработчику)

Нужны Java 21 и рабочий графический дисплей. На Linux без физического дисплея — Xvfb и Mesa. Это не бенчмарк RTX и не замена проверке на устройстве игрока.

1. Создайте отдельный Creative superflat-мир **KelMagicQA**, с деревнями и генерацией структур. Не используйте рабочее сохранение игрока. Выйдите из мира.
2. Визуальный прогон:
   ```bash
   JAVA_HOME=/path/to/jdk21 DISPLAY=:99 LIBGL_ALWAYS_SOFTWARE=1 bash ./gradlew -I tools/binary-build.init.gradle -I tools/native-qa-1.11.init.gradle runClient --max-workers=1
   ```
   Qa110 откроет только этот мир, запишет 30 сцен в `/data/native-qa-1.11/screenshots`, остановит клиент. QaLocate на серверном потоке проверит поиск неизученного архивного дома около (10000,10000) и выполнит настоящую locate-команду. Код не строит архив вручную. В обычном мире без нужных структур такой тест может завершиться ошибкой — не заменяйте её фиктивным PASS.
3. `tools/perf-qa.init.gradle` запускает два простых режима (HUD, HUD+100 слов), по 240 кадров прогрева и 239 измерений. Настройки 1280×900, без VSync, дальность6; не меняйте мир/нагрузку между сравнениями. Тест не доказывает ускорение на произвольной GPU. Отдельные стенды не запускайте одновременно с GameTestServer.

Все `dev/kelmagic/client/Qa*` исключены из JAR; свойства стендов по умолчанию выключены. Не разрешайте диагностике подменять производственные права, лимиты, защиту и игровые эффекты.
